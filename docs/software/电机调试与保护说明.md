# 电机调试与保护说明

更新日期：2026-10-15。修改前 Git 快照为 `a5059d7`，备份分支为 `codex/backup-motor-debug-20261014`，本批修改分支为 `codex/motor-debug-hardening`。

## 操作入口

手动页显示 X、Y 和所选电机的真实使能、闭环、寻零、到位、限位和故障状态，提供所选轴使能、去使能、故障复位和“XY轴回零”。所选轴可以与 X/Y 不同，状态会单独采集。“XY轴回零”按手动页速度与定位加速度，将当前映射的 X/Y 电机绝对定位到位置 0，两轴均确认到位后完成；不会发送 `P801=1`、执行机械寻零或重设当前位置。设置页提供 X/Y 联合使能/失能与“机械回零”；机械回零先发送 `ENABLE PLC 1`，等待至少 500 ms 后发送 `P801=1`，按 PLC 状态及两轴到位确认完成。

“诊断与配置”包含轴反馈与趋势、当前与历史报警、设备参数与 I/O 三页。底部当前报警提示跨页面可见，点击可跳转到报警列表；顶部显示运行条件不足的具体原因。

## 手动运动与动作确认

单步、连续点动、绝对定位和 HOMEZ 共用反馈与运动状态管理。动作前检查有效反馈、激活、使能、闭环、故障及已停稳状态；在通信线程真正执行前重新读取目标轴状态，避免只用界面旧值判断。

X/Y 的行程使用“设置”页已应用的毫米范围与 ct/mm 比例；其他电机必须先在诊断页配置计数行程。每轴可设最大点动速度和到位/稳定容差，默认容差为 0.5 ct。最大点动速度限制用于手动点动和定位；路径规划只设置目标速度，加速度由规划器根据路径几何和采样间距自动计算。更改 X/Y 的计数行程会同步到坐标范围并重新应用。

正限位禁止继续正向运动，负限位禁止继续负向运动。允许的退限位方向仍须满足目标行程和控制器规则。控制器期望位置/位置限位停止单独诊断；方向不明确时禁止自动猜测退出方向。上位机行程检查与轮询停止是辅助保护，实际减速距离、硬限位及软件限位应在控制器侧配置。

定位和单步发送成功后保持运动所有权，直到新反馈同时满足实际目标容差、期望速度为零和到位；通信接收成功不等于动作完成。HOMEZ 等待实际位置为零，但不表示完成机械寻零。使能/去使能、复位也要回读状态确认。

停止接收后继续保持“停止中”，至少两个新的位置样本稳定，并结合轴的期望速度零/到位和路径坐标系结束状态确认停稳。超时或停止失败保留锁定，可重试停止。断开和关闭窗口先确认停稳；无法确认时保留连接并提示处理。

PMAC 的 `J/` 兼有停止和闭环使能作用。停止前读取轴状态，未使能轴保持未使能；已使能开环轴使用 K 撤销输出。所有这些命令都经过同一通信队列，不能替代硬件急停或安全控制系统。垂直轴的抱闸与去使能顺序必须由实际控制器/驱动逻辑保证。

## 未到位与等待恢复

状态文字区分“指令运动中”“指令已停止，未到位”和“到位”。未到位仍阻止普通点动、定位与路径启动，但不再把恢复入口锁死。

窗口底部“解除等待并去使能”独立于到位位和缓存反馈的新鲜度。确认机械支撑与抱闸后取消待执行动作、停止本程序拥有的坐标系/回零 PLC，并对监测轴发送 K。至少两个指令接受后的新样本显示轴未使能、位置变化不超过每轴容差，且本程序拥有的坐标系退出运行后，才清除手动与路径等待状态。原动作标记取消，不继续运行。

恢复确认最多等待 5 秒，失败或反馈仍未知时保留运动锁定和明确原因。命令已返回后可重试；通信线程阻塞时指令仍会排队，此时不能仅凭界面按钮证明已去使能。恢复不会使用 HOMEZ 或改变坐标零点。

“手动控制”页新增“修复脉冲输出”。仅在实机去使能状态下，核对本地 Turbo PMAC2 的标志地址、PFM 模式、内部脉冲译码、反馈转换表来源，确定输出属于同一物理通道后才提供修复确认；物理通道不由电机号猜测。只将该轴 Ixx02 修正为对应的 C 通道地址，执行前再次核对状态和参数，写后回读。失败保持去使能，成功也保持去使能，不自动 SAVE。用户核对接线后使用现有使能按钮恢复闭环保持；依据 Turbo SRM 6-107，去使能后再 J/ 恢复闭环时以当前反馈位置建立新的保持位置。

2026-10-15 实机读取到 I102=$078002，而 I7016=3、I7010=8、I103/I104=$3515、I8020=$078000；此组合把控制量写到 A 通道，C 通道 PFM 命令为零。修复按钮对此组合提供 $078004，并保留确认过程。内部脉冲计数并非独立机械位置反馈，恢复后的实际机械位置仍应按设备测量确认。

## 反馈、趋势与通信异常

`#nP` 读取实际位置，`#nF` 读取跟随误差，单位均为编码器计数。跟随误差是期望位置减测量位置，精确到 0.1 ct；开环时控制器报告 0，此时不显示有效指令位置。界面中的估算指令位置使用 `P + F`；两条查询不是同步采样，不能用于伺服精度验收。速度仍由位置差估算。

轴反馈与趋势页显示三张图：指令与实际位置、速度–时间（v–t）、跟随误差。蓝色实线表示实际值，橙色虚线表示估算指令值。v–t 图用相邻位置样本的差值除以实际时间差并乘 1000，单位为 ct/s；这是该区间的平均速度估算，不是 PMAC 内部瞬时速度。缺帧、反馈过期或时间间隔超过 1 秒时不跨区间求速度。开环或缺少跟随误差时保留实际值，不绘制无效的指令值。

实时三图保留相同的最近 300 个通信样本，横轴使用各轴采样时间并以秒显示；切换电机时清空实时历史。小窗口可以滚动查看下方图形。完整录制独立于 300 点显示窗口，不会因滚动或切换页面丢失已录制数据。这些曲线用于趋势比较，不能替代 PMAC 内部同步采集来确认指令速度或机械振动。

### 诊断数据录制、回顾与图片导出

仅提供手动录制，设备运动不会自行开始或结束录制。点击“开始录制”后，包含现有反馈中的 X、Y 和所选电机，重复电机只存一次；可在运动开始前提前录制，也可在运行期间开始记录。

“开始录制”进入手动模式，直到点击“结束录制”或关闭窗口才结束；可以跨多次运动，也适用于其他软件启动的程序。通信中断期间不伪造采样，恢复后标记断点。录制期间约每秒刷新到磁盘，正常结束时关闭并刷新文件；异常退出时最后一次刷新后的数据可能缺失。单份文件最多 1000000 个轴样本，达到上限后结束保存。

文件默认写入 `%LOCALAPPDATA%\PMAC Operations Control\recordings\`，文件名包含来源、日期时间及唯一编号。诊断 CSV 首行包含 `pmac_diagnostics_v1`、`hardware`/`simulation` 与开始时间（UTC）；随后每行保存电机号、相对时间 ms、实际位置 ct、跟随误差 ct、两个状态字和断点标记。数据保留原始精度，缺失值留空。指令位置和速度在重绘时从原始数据重新计算。此格式独立于已有 XY 轨迹导出中的 `actual.csv`，回顾入口只接收诊断录制 CSV。

使用流程：

1. 点击“开始录制”后执行运动，完成后点击“结束录制”。状态行显示保存路径。
2. 点击“回顾最近记录”，或用“打开 CSV 回顾”载入以前的文件；无需连接设备。回顾时监控和后台录制继续运行。
3. 选择回顾电机和开始/结束秒数，点击“查看时间段”；“完整记录”恢复全时段。三张图使用同一时间范围，回顾数据不受 300 点限制。
4. “导出 CSV”复制当前回顾文件或实时录制文件；录制中导出会先刷新，得到当时的数据快照。“导出 PNG”把当前选定时间范围内的三张图、单位、来源和估算说明一起导出，包含滚动区域下方图形。
5. 点击“返回实时”恢复最近 300 点趋势，不修改设备状态。

### CSV 回顾偏差分析与综合评分

打开诊断 CSV 后，页面在曲线上方显示所选电机、所选时间段的平均误差、RMS、最大绝对误差及其发生时间、误差峰峰值、绝对误差 P95、超差时间及占比。修改开始/结束时间后约 200 ms 自动更新曲线和分析，无需再次点击“查看时间段”；切换电机或修改评分容差也会重新分析。计算在后台执行，过期计算结果不会覆盖最新选择。无效时间范围会清除旧统计，数据不足时显示“无法评分”。

误差直接取 CSV 的 `following_error_ct`，与“估算指令位置 − 实际位置”一致，不是独立同步测得的位置差。只使用使能、闭环且误差有效的数据；不跨 `gap_before`、缺失值或超过 1 秒的通信间隔计算时间统计。界面同时显示有效时长、所选时长及覆盖率，记录范围外和缺帧时间不当作零误差。

相邻有效采样之间采用线性误差模型，并在时间段边界处插值截取。平均误差为误差积分除以有效时长，RMS 为平方误差积分的均方根；P95 表示 95% 有效时长内绝对误差不超过该值。超差时长按 `|e| > T` 的实际插值时间计算，占比的分母是有效时长。峰值、峰峰值使用时间段内有效样本及插值边界，孤立有效峰值不会因为相邻缺帧而隐藏；最大值相同取最早时刻，时间以 CSV 起点为零点。

“评分容差”默认 **10 ct**，可直接修改；**0 表示未设置**，此时仍显示误差指标，但不计算超差时长与综合分数。综合误差评分范围 0～100，越高表示相对所设容差的误差越小，公式为：

`Score = 100 / (1 + 0.40 × RMS/T + 0.25 × P95/T + 0.15 × MaxAbs/T + 0.20 × ExceededRatio)`

其中 `T` 为评分容差，`ExceededRatio` 取 0～1。权重依次为 40%、25%、15%、20%，可点击“查看公式”核对；零误差得 100 分。此分数为软件自定义的相对比较指标，不是行业标准或设备精度合格判定，应在相同容差、相同运动阶段和足够数据覆盖率下比较。单个采样点或仅开环数据不足以支持时间统计，不会得到满分。

历史曲线导出 PNG 时包含当前时间段的六项指标、评分、容差及覆盖率；正在重算时暂停图片导出，避免图形与统计对应到不同时间段。小窗口可滚动查看三张曲线，录制方式仍然仅为手动开始/结束。

趋势保留最近 300 个通信样本。反馈超过 1 秒未更新，独立界面定时检查即标记数据过期/未知，并禁用运动；即使 COM 查询没有返回也会触发。运动过程中请求停止，但通信阻塞时停止仍须排队。通信恢复只恢复状态读取，不自动重启任务。实机重新连接后要重新确认并应用坐标。

协议依据为本地《TURBO PMAC(PMAC2) SRM（中文版）》印刷页 262–265、303–304、362。使能使用第一状态字 bit19；第二状态字 bit12 是期望位置限位停止；第一状态字 bit14 是数据块错误。

## 参数与设备配置

点动速度写入 `Ixx22` 后立即回读并比较。诊断页可单独回读所选轴实际点动速度。

手动点动、单步和定位先读取当前 `Ixx22`：与请求速度相同则直接发送运动命令，避免每次重复赋值；不同才执行写入及回读。每次仍读取真实速度，不跨操作缓存参数，外部软件或 PLC 修改速度后也会重新核对。

“应用所选轴参数”应用行程、最大速度、容差和复位命令。“保存设备配置”保存 X/Y 映射、比例、范围、全部单轴规则及 I/O 映射；“载入设备配置”只填回参数，需核对并重新应用坐标。配置不自动发送电机使能或运动命令。

配置目录为 `%LOCALAPPDATA%\PMAC Operations Control`，模拟配置 `simulation.xml` 与实机配置 `hardware.xml` 分开。实机连接时核对保存的 Pcomm 设备名称；该名称对应设备编号，不能取代现场核对控制器序列号及接线。

实机复位命令默认留空，需要依据实际驱动器与 PLC 的恢复流程填写，支持 `{motor}` 替换电机号。该指令应只执行故障恢复，不应启动运动。复位后回读故障状态；若发现运动请求或位置变化，立即请求停止并报告。模拟默认 `SIMRESET{motor}`，清除模拟故障后保持未使能。可在模拟命令栏使用 `SIMFAULT3` 注入 3 号轴故障验证，模拟指令不发送给真实设备。

## 报警、I/O 与日志

报警记录包含来源、时间、具体状态字、原因、建议、确认及恢复状态。确认只表示已经看见，不能清除仍存在的故障；设备反馈恢复后标记恢复。界面历史保留最近 1000 条，轴未被监测或断线时不会假定原报警已经恢复。

I/O 根据实际接线填写信号名称、M/P 查询变量和低电平有效选项，点击读取采集，最多 32 路。只允许读取变量，不允许在查询栏写入、启动 PLC 或执行运动。当前是按需诊断，不自动把未知接线的 I/O 变成运动安全联锁；原点、急停、安全门与抱闸信号须由现场映射并验收。

操作、报警及恢复记录自动追加到 `%LOCALAPPDATA%\PMAC Operations Control\logs\yyyyMMdd.log`，包含日期与毫秒时间。界面保留 500 条滚动尾部，清空界面不删除磁盘日志；写入失败会在日志界面报告。报警确认也写入操作日志。

## 点动反馈延迟优化

反馈采集由 `PathView` 的 50 ms 定时器驱动，`Form1` 的 100 ms 定时器负责界面刷新和独立超时检查；新反馈事件到达后会立即执行手动确认，无需再等 100 ms。手动动作及停止确认期间，采集定时器临时改为 25 ms；命令接受后立即请求一次反馈。WinForms 定时器和串行 COM 通信不保证实时周期，上一轮请求未结束时不会堆叠采集任务。

单轴手动动作和单轴停止优先读取当前轴的 `#nP`、`#n?`、`#nF`，一次常规确认从 6 条（X/Y）或 9 条（另选第三轴）查询减为 3 条。每 250 ms 到期后安排完整监测读取，更新其他轴；路径坐标系执行、多轴停止和等待恢复保留完整读取。逐轴采样时间保持独立，第三轴的新反馈不会改写 X/Y 的采样时间；上下文改变后丢弃旧请求。

动作前在通信线程重新读取实际位置与状态的保护保持不变。定位完成仍要求命令接受后的新样本同时满足 `VelocityZero`、`InPosition` 和软件目标容差；单轴停止仍需要至少两个接受后的新位置样本稳定。收到停止应答或看到位置不变都不会单独解除等待。

点动、定位和停止在日志中记录“耗时”：排队、实时检查、指令发送（含速度核对）、接受后首帧反馈、首次观察到控制器到位、总确认时间。时间来自上位机单调时钟；首次到位是上位机观察时刻，不是 PMAC 内部置位的精确时刻。定位等待超过 500 ms 时进一步区分“PMAC 尚未到位”和“PMAC 已到位、仍不满足上位机目标容差”。

Turbo SRM 的 I13（5-17～18）另提供伺服中断中的前台到位检查：默认 0 只运行后台检查；启用后使用另一状态位 bit13，不等同于当前后台到位位 bit0，且不执行 Ixx88 连续扫描等待，会增加伺服任务开销。本次仅优化上位机，不修改 I13、Ixx28 或 Ixx88。先前 1 号轴持续 100 ct 跟随误差、大于 10 ct 到位带的情况，需要解决输出/反馈配置，轮询加速无法使其到位。
