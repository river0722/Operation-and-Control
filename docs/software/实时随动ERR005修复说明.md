# 实时随动 ERR005 修复记录（2026-11-02）

触发日志：`PMAC 命令 [PVT 20] ... ERR005`。这表示控制器已收到命令，但该命令要求程序缓冲区已打开。后续“停止耗时（停稳确认）”是出错后的停止流程，不是原始故障。

原实现直接通过 PcommServer 发送 `PVT`、坐标和 `SPLINE1`，没有先建立、打开和启动运动程序缓冲区。模拟器有独立的数学轨迹入口，之前的模拟通过没有验证实机 ASCII 命令所处的上下文。

## 修复后的发送流程

1. 检查预留坐标系空闲、无错误且已到位；在关闭程序入口时设置轴映射和时间单位。
2. 首次使用该坐标系时通过 `DEFINE ROT 2048` 建立旋转缓冲区。本次连接内复用已建立的缓冲区。
3. 在入口关闭时执行 `&nB0`，再执行 `&n OPEN ROT`、`CLEAR`、`ABS`。
4. 写入完整的首个 PVT 或 Spline1 运动片段后发送 `&nR`。之后保持 ROT 入口打开，持续追加，保持边画边走。
5. 用 `&nPR` 检查未计算的程序行数。2026-11-02 后续修订：追加后将超过 48 行时暂缓写入，保留同一片段、50 ms 后重试；本次不写任何运动行，不清空、不重启流。连续 10 秒没有消化进展时才按故障清理；已启动的坐标系若意外停止或报告错误，不自动重启旧轨迹。
6. 允许明确的电机位置、跟随误差和状态查询与轨迹共享端口；禁止随动期间发送可能被当作运动程序内容的参数/变量命令。
7. 松开、故障或取消时关闭入口、发送坐标系中止，清理本次预留缓冲区并执行原有双轴停稳确认。初始化尚在通信线程执行时松开，也会排队中止；不再启动已取消目标。

`B0` 不可在 ROT 入口打开时发送，否则会被解释为 B 轴运动。`CLOSE` 的自动 RETURN 行为意味着不能用“每片段 CLOSE/重新打开”来声称连续流；正常拖动期间保持入口打开，停止时才关闭。

如果 `DEFINE ROT` 被拒绝，软件保留原始错误并报告 ROT/LOOKAHEAD/GATHER 的分配冲突，不会自动删除控制器的其他缓冲区。应核对现场的预留坐标系和缓冲区内存配置后再启动。

## 依据与验证范围

- [Turbo PMAC 软件参考手册](../../references/pmac/软件手册/TURBO%20PMAC(PMAC2)%20SRM.PDF)：PDF 第 113 页定义 ERR005；第 392、409、505、513 页说明 B0、DEFINE ROT、OPEN ROT 和 PR；第 395 页说明 CLOSE；第 612、624 页说明 PVT/SPLINE1 可用于 PROG 和 ROT。
- [Turbo PMAC 用户手册](../../references/pmac/用户手册/TURBO%20PMAC%20USER%20MANUAL.pdf)：PDF 第 62–64、353–354 页说明在线/缓冲命令和边加载边执行的旋转程序。
- `tests/SmokeTests.cs` 新增固件文本入口规则替身，复现无缓冲区时的 ERR005，并验证 PVT/Spline1 初始化、连续追加、查询隔离、积压保护、失败清理以及初始化期间取消。替身明确模拟 CLOSE 插入 RETURN，避免模拟器轨迹接口再次掩盖上下文错误。

这些是软件和协议模型检查；未通过此修复过程连接或驱动现场控制器。真实固件执行、缓冲区资源分配、轨迹连续性及运动精度仍需现场验证。

## 普通拖动触发积压保护的后续修订

用户实机反馈“实时随动缓冲积压过多”。旧实现逐个发送原始鼠标事件，而且碰到 48 行上限立即中止，没有实现等待消化后的继续发送。

- 输入整理缓冲改为 100 ms；在每个 60 ms 时间窗口内，依据 0.02 mm 的折线偏差上限合并冗余点。检查全部被合并点的投影和距离，保留明显转角、反向和闭环，保留最终端点。该偏差是输入几何简化预算，不是实机伺服精度。
- 按执行时长估计限制前送量：已提交的预计剩余时间超过 300 ms 时暂停提交，等待定时器再次调用，通信线程不阻塞等待。
- `FollowBufferBusyException` 仅表示暂时没有写入容量；应用保留完整的待发送片段，50 ms 后再次检查并重试。通信或轴/坐标系错误仍立即终止。
- Spline1 的每个新控制点仅提交一次；由 PMAC 维持样条前视，移除上位机重复发送重叠控制点的旧窗口生成器。整笔使用固定 `TM60`，远距离鼠标片段细分，避免靠改变 TM 处理速度限制。
- 主机队列的最老轨迹超过 15 秒或超过 10000 点时停止并明确说明原因，不静默丢弃早期点。鼠标松开仍中止所有待发送轨迹并确认停稳。
- 定向测试用可控时钟模拟 PVT/Spline1 各 8 秒、每秒 1000 个输入点，消费方最多保留 3 段，验证暂缓后继续、终点、折线几何偏差、取消、通信故障和真实超时。另用固件协议替身验证 PR 消化进展重置超时，只有持续无进展才中止。

## 按鼠标画速自动随动

后续按用户要求，真实 UI 入口改用 `CanvasFollower.BeginAuto`。距离使用画布 mm 坐标，时间使用采集鼠标点时的单调时钟时间戳，参考速度为 `distance / deltaTime`。上位机发送线程的排队或执行时间不参与输入画速计算。X/Y 轴分别读取配置的 `MaximumSpeed`（ct/ms），换算为 mm/s 后约束段时间；超过上限则延长段时间，保留路径端点，不自动提高设备配置上限。

“目标速度 mm/s”和手动点动速度不再控制鼠标随动。状态栏显示鼠标画速、调度参考速度和轴上限限速提示；参考速度不是实际伺服测速。PVT 使用按鼠标时间戳计算的段时间；Spline1 对该时间向上量化为 `TM60` 的整数倍，可能更慢。原有暂缓追加、队列保护和松开停止行为保留。

验证增加了两种插补下同长轨迹画速翻倍、X/Y 不同 counts/mm 与不同速度上限、超速时延长执行及终点保持检查。界面测试将离线规划速度设为 0.001 mm/s，仍验证自动鼠标随动能在正常时间到达目标，避免再次误用离线或手动速度字段。
