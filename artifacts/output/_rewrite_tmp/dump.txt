[P0|Normal] 5.1 用户需求与技术需求
[P1|Normal] 基于 Turbo PMAC 双轴运动控制上位机
[P2|Heading 1] 5.1.1 目标用户与典型使用场景
[P3|Normal] 本项目面向参与运动控制实验的学生、负责实验指导的教师以及设备调试人员。学生需要完成图形输入、运动参数设置、轨迹运行和实验数据分析；教师需要依据运行过程与导出数据检查实验结果；调试人员则需要查看轴状态、执行手动定位、定位异常原因并保存设备配置。因而，上位机需要同时支持图形运动实验和设备调试，并为实验结果提供可追溯的数据记录。
[P4|Normal] 系统的典型使用场景包括模拟验证、实机调试和双轴轨迹复现。在模拟验证阶段，用户通过模拟模式检查图形导入、轨迹规划和数据分析流程；在实机调试阶段，用户连接控制器，核对轴号、坐标比例和行程范围，随后进行使能、点动、定位及机械回零；在轨迹复现阶段，用户绘制图形或导入 DXF 文件，生成 PVT 或 SPLINE1 运动程序，执行后比较输入轨迹、规划轨迹与控制器反馈轨迹。
[P5|Normal] 上述场景形成“输入任务—检查条件—生成规划—执行运动—采集反馈—分析结果”的任务链。前一阶段的结果是后一阶段的依据：图形和参数未经检查，不能直接用于运动；控制器接受命令，不等于机械动作完成；只有保留规划数据与反馈数据，才能解释轨迹偏差并复核实验结论。
[P6|Heading 1] 5.1.2 核心任务与使用限制
[P7|Normal] 本上位机的核心任务是将二维图形转换为双轴运动任务，并提供执行过程监测、异常处理和结果分析。上位机负责交互、规划、程序传输与反馈展示，双轴同步插补由 PMAC 控制器执行。
[P8|List Number] 运行环境：软件采用 C# WinForms，目标框架为 .NET Framework 3.5，运行平台为 x86；实机模式依赖正确安装和配置的 32 位 PcommServer 及相关驱动。
[P9|List Number] 图形输入范围：支持自由绘图、直线、圆、圆弧、五角星和规定范围内的 ASCII DXF 实体。DWG 文件须先转换为 ASCII DXF；块、文字、标注、三维实体及不支持的样条类型不能直接导入。
[P10|List Number] 工艺范围：当前实现二维路径运动，多笔画之间包含定位转移，尚未提供抬笔或刀具开关控制，因此不能直接将其视为完整的加工工艺系统。
[P11|List Number] 实机配置条件：实机运行前须核对电机号、方向、计数与毫米的换算比例、允许行程、回零参数以及专用坐标系和程序号。模拟默认参数不能直接作为实机参数使用。
[P12|List Number] 反馈与精度边界：X、Y 反馈通过通信顺序读取，不属于同步锁存采样；当设备采用内部脉冲计数反馈时，显示位置也不能直接作为独立的机械位置测量结果。机械定位精度和回零重复性需通过实机测量验收。
[P13|List Number] 停止功能边界：软件停止依赖通信和控制器响应，不能替代硬件急停。模拟器用于验证软件流程，不解释任意用户程序或 PLC，模拟运行结果不能代替控制器固件执行验证。

[P0|Title] 5.2 功能模块规划与工艺流程
[P1|Normal] 本系统采用 C# WinForms 与 Turbo PMAC 构成二维运动控制平台。模块规划围绕“图形如何成为可执行轨迹、执行结果如何被确认”展开：上位机负责图形解析、轨迹与时间规划、程序生成、任务管理和结果分析；PMAC 负责程序解释、双轴同步插补、伺服运算及控制输出。
[P2|Heading 2] 5.2.1 功能模块划分及关系
[P3|Normal] 系统以 DrawingPath 保存输入图形，以 MotionPlan 保存规划及程序，以 TrajectoryRun 保存一次运行及其反馈。主流程由这三类数据连接，手动调试、设备配置和统一反馈通过共享操作状态参与运行管理，功能关系见图5-1。

[P15|Heading 2] 5.2.4 工艺步骤与关键判断
[P16|Normal] （1）设备准备与输入建立
[P17|Normal] 用户选择模拟或实机模式并连接设备，核对 X/Y 轴号、计数与毫米比例、行程、专用坐标系及程序号。完成配置后，通过自由绘图、典型图形或 ASCII DXF 建立输入路径。绘图只改变路径数据，默认不触发运动；鼠标跟随需单独启用。
[P18|Normal] （2）文件解析与轨迹处理
[P19|Normal] DXF 解析器按实体类型提取线段、圆弧、圆、多段线及支持的样条，并按文件单位或指定比例换算为毫米坐标。几何模块执行平移、缩放、重采样和行程检查，形成带笔画信息的 DrawingPath。遇到不支持的实体、异常数据或越界路径时，显示原因并停止后续流程。
[P20|Normal] （3）速度与时间规划
[P21|Normal] 规划器根据路径、当前位置、点间距、速度和加速度上限建立 PVT 或 SPLINE1 轨迹。多笔画之间加入定位转移段。PVT 在急转角降低至停速；SPLINE1 对路径进行圆滑处理，不能要求其经过所有输入点。规划同时检查曲线极值和行程，必要时延长段时间，以满足约束。
[P22|Normal] （4）程序生成与启动复核
[P23|Normal] 程序生成器将规划转为轴映射、绝对坐标、插补模式、位置、末速度和时间等语句，供用户预览。图形、规划参数或规划起点变化后须重新规划。启动前检查连接、反馈新鲜度、配置确认、轴使能/闭环、故障和到位状态；在通信线程实际执行前再次读取状态，检查当前位置与规划起点的距离不超过 0.01 mm，并确认预留坐标系空闲。
[P24|Normal] （5）下发与控制器执行
[P25|Normal] 实机流程将程序写入临时文件，通过 PcommServer 下载，下载成功且任务未取消后，再发送坐标系程序启动命令。PMAC 按自身周期解释程序并执行双轴同步插补及伺服运算。模拟模式直接执行数学规划模型，用于验证流程，不能据此证明任意下载程序或用户 PLC 已被正确解释。
[P26|Normal] （6）反馈监测、完成及停止
[P27|Normal] 上位机定期查询位置、轴状态和坐标系状态，记录采样时间并更新实际轨迹。正常完成需同时满足规划时间条件、轴与坐标系到位、坐标系程序不再运行、终点偏差不超过 0.05 mm，且未检测到阻止运行的故障。故障、越界、超时或停止请求进入中止流程；发送停止后继续等待连续新反馈确认，失败时保留锁定并提示重试。通信恢复后不自动续跑。
[P28|Normal] （7）分析与数据留存
[P29|Normal] 运行结束或中止后，依据 MotionPlan 与 TrajectoryRun 计算时间配对误差、轮廓偏差、滞后和查询统计，导出原始点、规划段、实际反馈、分析报告及本次程序。中止记录标为未完整运行。位置由两轴顺序查询取得，其时间并不完全一致，因此分析结果用于过程诊断，机械精度仍需同步采集或外部量具验收。
[P30|Heading 2] 5.2.5 接口与数据流说明
[P31|Normal] 主数据流为 DrawingPath → MotionPlan → PMAC 程序 → ControllerFeedback → TrajectoryRun → AnalysisResult。其间既传递运动数据，也传递状态与取消信息；文件下载成功仅表示传输阶段成功，后续运行和完成还需状态反馈证明。

[P47|Normal] 这些结果直接证明本组异常输入被识别。DWG、二进制 DXF、其他未支持实体、文件大小与点数限制的说明来自当前源码审查，本次未对每一种边界另做独立文件试验，不将其写成本次全部实测通过。
