[Heading 1] 5.1 用户需求与技术需求
[Normal] 基于 Turbo PMAC 的双轴运动控制上位机
[Normal] 本节先说明谁在用这套软件、要完成什么、受哪些限制，再列用户需求与技术需求，最后给出需求、功能和测试用例的对应关系。
[Heading 2] 5.1.1 目标用户与典型场景
[Heading 3] 目标用户
[Normal] 学生做图形输入、参数设置、轨迹运行和结果分析；教师依据运行过程和导出数据检查实验；调试人员查看轴状态、手动定位、排查异常并保存设备配置。三类人共用一套软件，因此上位机既要支撑实验，也要支撑调试，并留下可追溯的记录。
[Heading 3] 典型场景
[Normal] 模拟验证：不接设备，走通导入、规划和数据分析。
[Normal] 实机调试：连接控制器，核对轴号、比例、行程，再做使能、点动、定位和机械回零。
[Normal] 轨迹复现：绘图或导入 DXF，生成 PVT 或 SPLINE1 程序，比较输入、规划和反馈三条轨迹。
[Normal] 三个场景串成一条链：输入 → 检查 → 规划 → 执行 → 采集 → 分析。前一步的结果是后一步的依据；控制器接受了命令，也不等于机械动作已经完成。
[Heading 2] 5.1.2 核心任务与使用限制
[Normal] 核心任务是把二维图形变成双轴运动任务，并在执行中监测状态、处理异常、保存结果。上位机负责交互、规划、传输和显示，双轴同步插补由 PMAC 执行。
[Normal] （1）运行环境：C# WinForms，.NET Framework 3.5，x86；实机模式需 32 位 PcommServer 及驱动。
[Normal] （2）图形输入：支持自由绘制、直线、圆、圆弧、五角星和规定范围的 ASCII DXF。DWG 须先转 ASCII DXF；块、文字、标注、三维实体和部分样条不能导入。
[Normal] （3）工艺范围：只做二维路径和笔画间的定位转移，没有抬笔或刀具开关，不能算完整的加工系统。
[Normal] （4）实机配置：运行前须核对电机号、方向、ct/mm 比例、行程、回零参数和程序号；模拟参数不能直接当实机参数用。
[Normal] （5）反馈与精度：X、Y 顺序读取，不是同步锁存；内部脉冲计数不等于独立的机械测量，定位精度和回零重复性须现场测量。
[Normal] （6）停止与仿真：软件停止依赖通信，不能替代硬件急停；模拟器只验证软件流程，不等于控制器固件执行。

[Heading 1] 5.2 功能模块规划与工艺流程
[Normal] 本节说明图形怎样变成可执行轨迹、执行结果又怎样被确认。上位机管解析、规划、程序生成、任务管理和结果分析；PMAC 管程序解释、双轴插补、伺服运算和输出。

[Normal] 系统用三类数据串联模块：DrawingPath 存输入图形，MotionPlan 存规划和程序，TrajectoryRun 存一次运行及反馈。手动调试、设备配置和统一反馈通过共享操作状态参与运行管理。图5-1 上半部分是上位机的七个功能域，下半部分是 Turbo PMAC；图底注明三条边界：通信应答不等于动作完成，软件轮询不等于伺服周期，硬件急停由独立安全回路承担。

[Heading 2] 5.2.2 模块输入、输出与协作
[Normal] 模块之间只通过数据对象和业务接口交换信息：界面提请求，业务服务检查条件并组织执行，通信会话访问设备；算法模块不直接操作界面或控制器。

[Normal] 图5-2 是从输入到反馈的主流程，分三段：上位机准备下发、PMAC 执行、上位机监测留存。解析或规划失败返回修改，启动条件不足不下发，运行后分正常完成与异常/停止两路。
[FigCaption] 图5-2  图形输入、运动执行与状态反馈工艺流程
[Heading 2] 5.2.4 七个工艺步骤与关键判断
[Normal] （1）设备准备与输入建立：选模拟或实机模式并连接，核对 X/Y 轴号、ct/mm 比例、行程、坐标系和程序号，再用绘图、典型图形或 DXF 建立路径。绘图只改数据，不动电机；鼠标跟随单独启用。
[Normal] （2）文件解析与轨迹处理：解析器按实体取出线段、圆弧、圆、多段线和受支持的样条，按文件单位或指定比例换成毫米；几何模块做平移、缩放、重采样和行程检查，形成带笔画的 DrawingPath。不支持的实体、异常数据或越界路径显示原因并停止。
[Normal] （3）速度与时间规划：按路径、当前位置、点间距和速度、加速度上限生成 PVT 或 SPLINE1，笔画间插入定位转移。PVT 在急转角降到停速；SPLINE1 做圆滑，不保证过所有输入点。规划同时检查曲线极值和行程，超限就延长时间。
[Normal] （4）程序生成与启动复核：规划写成轴映射、绝对坐标、插补模式、位置、末速度和时间的程序文本供预览；图形、参数或起点变了必须重新规划。启动前检查连接、反馈新鲜度、配置确认、轴使能与闭环、故障和到位，执行前再确认当前位置与规划起点相距不超过 0.01 mm、预留坐标系空闲。
[Normal] （5）下发与控制器执行：实机把程序写入临时文件，经 PcommServer 下载，成功且任务未取消才发送坐标系启动命令。PMAC 按自己的周期解释程序，完成插补和伺服运算。模拟模式跑数学规划模型，只验证流程。
[Normal] （6）反馈监测、完成与停止：定时查询位置、轴状态和坐标系状态，记采样时刻并更新实际轨迹。正常完成要满足：规划时间到、轴与坐标系到位、坐标系程序已停、终点偏差不超过 0.05 mm、无阻止运行的故障。故障、越界、超时或停止请求进入中止流程，发出停止后等连续新反馈确认；确认不了就保持锁定并提示重试，通信恢复后不自动续跑。
[Normal] （7）分析与数据留存：结束后用 MotionPlan 和 TrajectoryRun 算时间配对误差、轮廓偏差、滞后和查询统计，导出原始点、规划段、实际反馈、分析报告和程序，中止的运行标为“未完整运行”。两轴顺序读取，时间不完全一致，结果用于过程诊断，机械精度另测。
[Heading 2] 5.2.5 接口与数据流
[Normal] 主数据链：DrawingPath → MotionPlan → PMAC 程序 → ControllerFeedback → TrajectoryRun → AnalysisResult。下载成功只说明传输成功，运行和完成还要靠状态反馈证明。
[TableCaption] 表5-5  主要接口与数据流
<TABLE 8x3>
   | 数据流 / 接口 | 发送方 → 接收方 | 内容与处理规则
   | 图形数据 | 界面 / DxfReader → PathGeometry | DrawingPath：毫米坐标、笔画和点列；DXF 按 $INSUNITS 或指定比例换算。
[Normal] 单位：轨迹用 mm、mm/s、mm/s²，规划时间用 ms；控制器位置是 ct，按各轴 ct/mm 换算，手动界面的计数参数不能与毫米参数混用。

[Heading 1] 5.3 上位机绘图与CAD文件读取
[Normal] 本节讲图形怎么进系统：在画布上自由绘制或添加典型图形，或读入规定范围的二维 ASCII DXF。两条通道最后都变成以毫米为单位、按笔画组织的点列，交给轨迹处理。DWG 不直接读取。
[Heading 2] 5.3.1 典型图形与自由绘制
[Normal] 界面可参数化添加直线、圆、圆弧和五角星：直线给起点和终点，圆给圆心和半径，圆弧再加起始角和扫角。自由绘制时左键按下记一笔，拖动时把屏幕坐标换算成毫米，松开、移出绘图区或失去焦点即结束。撤销删最后一笔，清空删除全部输入。

[Normal] 文件选择器只列 *.dxf，DxfReader 还会再查扩展名、文本结构和实体内容。能读 ASCII DXF；DWG 要另存为二维 ASCII DXF，并删文字、标注、分解块。能否导入主要看几何定义，与 AutoCAD 版本关系不大。

[Heading 2] 5.3.3 文件与数值限制
[Normal] 文件限制：单个文件不超过 16 MB，单条路径不超过 20000 点；组码与值成对出现，文件须含 ENTITIES 和 EOF。解析器检查非有限数值，几何校验要求变换后坐标绝对值不超过 1 000 000 mm。这个上限只管输入有效性，设备行程在规划时另查。
[Normal] 单位：取自 HEADER 的 $INSUNITS，支持无单位、英寸、英尺、毫米、厘米、米、mil 和微米。无单位文件用用户给的“毫米/文件单位”比例，未支持的单位编号会提示转毫米。二进制 DXF 和原生 DWG 尚未实现。

[Heading 2] 5.3.6 解析与坐标转换
[Normal] 解析分两步：把 DXF 文本变成“组码—值”序列，再识别 HEADER 单位和 ENTITIES 实体。LINE 的 10/20 是起点、11/21 是终点；ARC 和 CIRCLE 的 10/20 是圆心、40 是半径，ARC 另用 50/51 表示起止角；LWPOLYLINE 的 70 是标志、90 是顶点数、42 是 bulge。各实体最后都转成同一种二维点列。
[Normal] 圆弧按弦差离散，界面传 0.01 mm，单步圆心角不超过 10°；多段线保留顶点顺序，bulge=b 按 θ=4·arctan(b) 还原；样条用控制点、节点和权重求值，非零节点区间预分段后按中点偏差自适应细分。
[Normal] 设文件单位到毫米的比例为 u，则 (x_mm, y_mm) = u(x_d, y_d)；需要平移或缩放时，PathGeometry.Transform 再执行下式，其中 s>0，Δx、Δy 以毫米计：
[Formula] x′ = s·x_mm + Δx        y′ = s·y_mm + Δy

[Normal] 画布：保持 X/Y 相同的物理比例，并把屏幕向下的 Y 轴翻成毫米向上的 Y 轴。设绘图区左、下边界为 L、B，宽高为 W、H：
[Formula] x_screen = L + (x_mm − X_min)·W / (X_max − X_min)
[Formula] y_screen = B − (y_mm − Y_min)·H / (Y_max − Y_min)
[Normal] 自由绘制用它的逆变换。屏幕像素不是电机计数，笔画精度还受像素分辨率限制。
[Normal] 数据结构：DrawingPath 记录来源 Source 和笔画 Strokes，每笔是有序的 MotionPoint(X,Y) 列表，单位 mm。绘图数据不含时间、速度和伺服指令；设备计数按各轴 ct/mm 换算，不等同于独立的 G54 工件坐标系。
