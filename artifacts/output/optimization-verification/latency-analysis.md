# 点动反馈延迟分析与修改

日期：2026-10-15。保留现有界面样式、按钮和布局。本次未向 PMAC 实机发送运动、使能、停止、恢复或参数赋值命令。

## 原来的实现

按键后，动作进入唯一 STA 通信队列，在执行线程重读目标轴位置和状态，通过保护后写速度、回读速度、发送点动/定位命令。随后保留动作所有权，等待新反馈满足 PMAC 期望速度为零、后台到位位和软件位置容差。连续点动松开后发送停止，再用至少两个新的稳定位置样本确认停稳。

采集由 PathView 的 50 ms 定时器驱动，Form1 的 100 ms 定时器负责显示及超时检查。一次完整反馈包含 6 条 X/Y 查询；另选第三轴则为 9 条。查询经 PcommServer.GetResponseEx 串行发送，只有全部返回才交付反馈；因此完整读取、排队、定时调度和控制器本身到位时间会叠加。

## 修改后

| 项目 | 原来 | 修改后 |
| --- | --- | --- |
| 手动运动采集间隔 | 50 ms | 25 ms；空闲及路径模式保持 50 ms |
| 单轴常规反馈 | X/Y/所选轴完整读取，6～9 条 | 当前轴 P/?/F，3 条；每 250 ms 到期安排完整读取 |
| 命令接受后首帧 | 等采集定时器 | 立即请求；已有请求运行时继续共享该请求 |
| 速度核对 | 每次写入再回读，2 条 | 先读实际值；相同 1 条，不同才写入并回读 |
| 发送前保护 | 通信线程重读位置和状态 | 保留 |
| 到位及停稳条件 | PMAC 到位、期望速度零、软件位置/稳定容差 | 保留；第三轴以独立反馈时间确认 |
| 耗时定位 | 无分阶段记录 | 日志增加排队、检查、发送、首帧、到位观察、总耗时 |

25 ms 是请求调度间隔，不是实机端到端延迟承诺。仍只有一个未完成查询，且 COM 和网络耗时可能使实际间隔更长。完整采样与单轴采样都不是同一伺服周期的原子快照。

## 持续未到位与其他优化空间

先前实机读取：1 号轴 P=0、F=100、V=0、状态 892000070400，I128=160 对应 10 ct 到位带、I188=0；持续 100 ct 跟随误差不会进入到位带。输出配置 I102=$078002 与 C 通道 PFM 反馈配置冲突，详细数据见 [实机诊断](../pmac-live-diagnosis/diagnosis.md)。这属于控制器未到位，不能把它解释成网络回报慢，也不能通过提高轮询频率解决。

软件默认目标容差为 0.5 ct，比此次 PMAC 的 10 ct 到位带更严格。若“首次到位”已记录而总确认仍迟迟不结束，应核对实际机械精度要求与软件目标容差，不应盲目放宽。

Turbo SRM I13 前台到位检查运行在伺服中断，使用 bit13，当前后台到位检查使用 bit0。前台检查不包含 Ixx88 连续扫描要求并增加控制器负担；本次未启用。后续可结合实测耗时评估前台检查以及组合 ASCII/内存读取；组合读取须先验证固件和多返回解析，不能假设是原子快照。
