# PMAC 上位机模块化架构与维护说明

本次重构保留原有 WinForms 页面、控件、设计器、资源、布局和操作入口，继续使用 .NET Framework 3.5 / x86。变化集中在职责划分、反馈复用和业务流程的独立测试。

## 模块职责

| 目录 | 主要文件 | 职责 |
| --- | --- | --- |
| Views、Controls、Form1 | PathView、MotionView、CanvasView、MotionCanvas、CanvasProjection | 读取输入、显示状态、绘制轨迹、处理鼠标/键盘和文件对话框；屏幕坐标换算属于 Controls |
| Application | OperationState、ManualMotionService | 共享操作互斥状态，串行提交手动操作，保持连续点动按下/松开的顺序，断开前停止并清理连接 |
| Application | MotionWorkflow | 路径启动、运行记录、完成判定、故障/限位/越界/超时停止、回零状态变化与到位判定、停止重试 |
| Application | FeedbackService | 所有页面共用的反馈源，同一时刻最多一个查询，丢弃断开或轴映射变化前的旧结果 |
| Application | CanvasFollower、MotionPlanningService | 合并鼠标跟随目标；组合独立规划算法与 PMAC 程序生成 |
| Communication | IControllerSession、ControllerSession | 对业务层提供设备操作契约，封装命令、反馈解析、程序启动和停止；实际设备访问通过 Execute 排队 |
| Communication | StaCommandDispatcher | 内部 STA 消息循环、工作排队和完成结果分派 |
| Communication | IControllerTransport、PcommTransport、SimulatorTransport、PmacProgramWriter | 设备传输、模拟能力及 PMAC 程序文本生成 |
| Motion | PathGeometry、TrajectoryPlanner、TrajectoryAnalysis | 图形生成与采样、运动分段与边界校验、轨迹误差和滞后计算 |
| Files | DxfReader、ProgramFileStore、RunDataExporter | DXF 导入、UTF-8/GBK 程序读写、下载临时文件、报告与完整采样导出 |
| Models | ControllerFeedback、DeviceStatus、PathModels、CanvasModels | 坐标、机械比例、路径、计划、运行记录及反馈数据；不引用 WinForms 或 System.Drawing |

界面通过业务服务和 IControllerSession 使用设备。Motion 只依赖 Models，Files 的 DXF 解析与导出可以使用 Motion；业务服务组合这些模块。Form1 负责装配共享服务并把结果绑定到页面。当前仍是一个项目，模块边界通过目录、命名空间、接口和测试维护。

## 主要调用关系

| 用户操作 | 调用路径 |
| --- | --- |
| 点动 | MotionView → Form1 → ManualMotionService → IControllerSession.Jog / Stop |
| 鼠标跟随 | MotionCanvas → Form1 → CanvasFollower → IControllerSession.MovePair |
| 导入与规划 | PathView → DxfReader / PathGeometry → MotionPlanningService → TrajectoryPlanner → PmacProgramWriter |
| 路径运行 | PathView → MotionWorkflow → IControllerSession.StartPlan |
| 机械回零 | PathView → MotionWorkflow.StartHoming → IControllerSession.Home |
| 反馈刷新 | 页面定时请求 → MotionWorkflow.Poll → FeedbackService → ReadFeedback → 运行监测、顶部位置、读数和实际画布 |
| 文件操作 | 界面文件对话框 → ProgramFileStore / RunDataExporter |

Form1 的刷新定时器只显示已取得的反馈，不再建立另一条查询链。共享 FeedbackService 同时返回 X/Y 的设备状态、位置、查询时刻和所选电机读数；选择 X 或 Y 为当前电机时，复用同一份采样。

## 线程与生命周期约定

1. 界面及业务服务的状态在应用线程上访问。业务服务不持有 Control，也不创建界面控件。
2. Form1 在创建 ControllerSession 时显式传入 WindowsFormsSynchronizationContext。Execute(action, completed) 将设备工作提交到唯一 STA 线程，再将完成结果回送到配置的应用上下文，即使调用当时 SynchronizationContext.Current 为空也保持正确线程。默认构造会话会捕获构造线程的上下文；未配置上下文的后台宿主应传入自己的应用线程上下文，无上下文时完成回调在通讯线程执行。
3. StaCommandDispatcher 内部仍使用隐藏 WinForms Control 和消息循环满足 COM 要求。这是内部实现，不出现在业务接口中。
4. 点动、跟随、下载、反馈和停止共享通讯队列。取消使用代次标记丢弃旧目标、旧查询和启动完成结果。
5. 窗口关闭仍先停止活动流程、断开设备，再释放反馈与通讯服务。FeedbackService 和 MotionWorkflow 释放后不会向页面投递新事件。

## 状态与停止

OperationState 是手动操作、点动、跟随、后台计算、路径运行、回零、停止和关闭状态的共同来源。按钮状态从这些状态派生，业务操作入口也检查互斥条件。

MotionWorkflow 保存当前运行拥有的坐标系和回零操作。停止失败时保留操作归属及锁定状态，禁止开始另一项运动，允许再次点击停止。内置 HOME 与 PLC 回零都遵循这个规则。正常完成必须满足原有位置、到位、坐标系空闲等条件；回零必须观察到本次状态变化，不能仅凭旧 Home Complete 位宣布成功。

软件停止仍通过通讯队列发送。实机通信、机械标定、回零和运动精度继续按原验收文档在设备上验证。

## 开发与验证

在 online 目录运行：

```powershell
.\build.ps1 -Test -ScreenshotDirectory "$env:TEMP\pmac-modular-verification"
```

| 检查程序 | 验证内容 |
| --- | --- |
| SmokeTests | 页面、设计器、布局、STA 执行/应用上下文回调（含空环境上下文）、手动控制、快速点动释放、鼠标跟随与窗口关闭 |
| WorkflowTests | DXF、PVT/Spline、轨迹误差、运行/回零/停止、完整采样和数据导出 |
| ModuleTests | 无窗口条件下的运行完成、故障停止、过期反馈、启动取消、停止重试、回零变化/超时、共享查询、编码及临时文件清理 |

新增业务功能时优先扩展 Application，并通过 IControllerSession 注入可控假设备。新增运动算法放在 Motion；新增控制器相关格式放在 Communication。界面事件只负责收集输入和显示结果，避免将完成判定、回零超时或设备状态互斥重新写回页面。

主窗体现明确配置界面回调上下文，并有检查覆盖调用时上下文为空的情形。停止失败时保留业务归属、允许重试，也有独立检查覆盖。
