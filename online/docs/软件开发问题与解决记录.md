# PMAC 上位机软件开发问题与解决记录

更新日期：2026-10-13。

项目采用 C# WinForms、.NET Framework 3.5 / x86。本文依据当前源码、已有自动检查及主窗口整合时的排查记录，整理实现中处理的工程问题和实际发现的缺陷。已完成的验证使用模拟器，实机尚未联调。

## 1. 开发环境与设备通信

| 问题与原因 | 解决方法 | 验证结果或边界 |
| --- | --- | --- |
| 旧工程需要兼容 .NET Framework 3.5，同时实机依赖 32 位 COM 组件 | 保留原目标框架，Debug / Release 均指定 x86；使用兼容 C# 3.0 的实现；构建脚本自动寻找 MSBuild | Debug、Release 编译通过；部署电脑仍需启用 .NET Framework 3.5 |
| 没有安装 PMAC 驱动时，无法开展实机通信验证 | 定义统一传输接口，分别实现 PcommServer 和模拟传输；COM 使用运行时绑定，使编译和模拟不依赖本机已安装的 COM 组件 | 无实机环境下可完成软件验证；PcommServer 调用仍需实机确认 |
| 直接在界面线程通信可能卡住窗口；COM 对象也有线程约束 | 设置独立 STA 通信线程，在同一线程创建、调用和释放 COM；完成后通过 BeginInvoke 更新界面 | 模拟检查覆盖异步连接、读取、命令和关闭；实际通信耗时待测 |
| 空应答、带长度的状态值和控制器错误容易被混为一谈 | 对 PcommServer 状态按无符号值提取高位状态；允许有效空应答，识别异常状态、ERR 和报警字符 | 已检查空应答成功、超时、非匹配应答及控制器拒绝命令；具体驱动版本待验 |
| 绘图目标不断产生，逐条排队会使平台追赶过时目标 | 鼠标跟随只保留最新待发送目标，同类请求未完成时不继续积压；用代次标记跳过已取消目标 | 已检查阻塞通信队列后取消绘图，旧目标不会重新启动运动 |
| 快速按下再松开点动按钮时，停止可能先于启动被处理；失焦也可能漏掉停止 | 启动和停止进入同一串行队列；鼠标松开、捕获丢失、窗口失焦、键盘释放都发送停止请求；连续点动时保留按钮可用状态 | 快速按放、连续点动、捕获丢失和失焦停止检查通过 |
| 设计器构造主窗体时不应启动控制器服务 | 检测设计模式，跳过通信会话和运行期初始化；保留控件布局文件及无通信服务的 PathView 构造函数 | DesignSurface 检查通过，主窗体设计模式下 session 为 null |

相关实现：[ControllerSession.cs](<../Operations Control/Services/ControllerSession.cs>)、[PcommTransport.cs](<../Operations Control/Services/PcommTransport.cs>)、[CanvasFollower.cs](<../Operations Control/Services/CanvasFollower.cs>)、[ControllerModels.cs](<../Operations Control/Models/ControllerModels.cs>)。

## 2. 绘图、坐标与 CAD 导入

| 问题与原因 | 解决方法 | 验证结果或边界 |
| --- | --- | --- |
| 屏幕像素、毫米和电机计数的单位不同，屏幕 Y 方向也与机械坐标相反 | 统一通过 CanvasSettings 完成屏幕↔mm↔ct 换算；X/Y 分别设置 ct/mm；画布保持物理比例，正 Y 向上 | 坐标往返换算、独立比例及范围检查通过 |
| 未知实机参数不能沿用模拟的 100 ct/mm 和 ±10 mm | 切换实机模式后要求填写并应用实际比例和行程；修改参数或实机电机映射后使标定失效；路径运行、使能和回零需要确认配置 | 缺少实机标定时相关控件禁用；手动运动尚未统一采用此门槛 |
| 自由绘图需要保留多个笔画，不能把所有点直接连成一条线 | 用独立笔画列表保存输入；画布增加笔画开始/结束事件和路径读取/加载；支持撤销最后一笔 | 规划器可处理多笔画，输入模型与运行数据分开保存 |
| DWG 不能按普通文本直接解析，CAD 文件范围需要先明确 | 按约定先实现 ASCII DXF，支持 LINE、ARC、CIRCLE、LWPOLYLINE、二维 POLYLINE 和非周期控制点 SPLINE | DXF 样例可导入并生成两种规划；DWG 仍需先转换 |
| DXF 中的英寸、米或无单位坐标可能造成尺寸错误 | 读取 $INSUNITS 并换算为毫米；无单位文件使用用户指定比例；对未知单位明确报错 | 英寸及无单位比例换算检查通过 |
| 多段线 bulge 表示圆弧；样条控制点也不能直接当作运动点 | 根据 bulge 计算圆心和扫角，展开闭合边；样条按节点、次数和权重求值，并按弦差自适应采样 | 正 bulge 半圆、闭合多段线、样条端点和已知曲线形状检查通过 |
| 静默跳过块、文字或三维实体会使运行图形缺失 | 对不支持实体、倾斜法向、三维输入、二进制 DXF、缺失字段和不完整文件明确拒绝 | 异常文件检查通过；需在 CAD 中清理、分解或转换后再导入 |
| 极大坐标或极小采样间距可能导致点数溢出和计算失控 | 检查有限数值、合法参数和采样数量，在危险的整数转换前拒绝异常输入；限制 DXF 文件为 16 MB、输入点数为 20000 | NaN、极大圆弧、极长重采样和畸形文件检查通过 |

相关实现：[CanvasModels.cs](<../Operations Control/Models/CanvasModels.cs>)、[MotionCanvas.cs](<../Operations Control/Controls/MotionCanvas.cs>)、[DxfReader.cs](<../Operations Control/Services/DxfReader.cs>)、[PathGeometry.cs](<../Operations Control/Services/PathGeometry.cs>)。

## 3. 路径规划、状态与运动控制

| 问题与原因 | 解决方法 | 验证结果或边界 |
| --- | --- | --- |
| 连续发送 X/Y 独立 J= 目标不能保证完整路径同步复现 | 鼠标跟随保留为即时双轴目标更新；完整路径生成 PMAC 坐标系 PVT / SPLINE1 程序，按统一时间插补 | 模拟双轴共享规划时间，完整 DXF→Spline→反馈流程通过；固件执行待验 |
| 当前轴位置与图形起点可能不同，多笔画之间也存在间隔 | 将当前位置作为规划初始位置，并加入到各笔画起点的转移段；启动前重新读取位置，变化超过 0.01 mm 则要求重新规划 | 规划段位置连续；转移段有明确标记，当前没有抬笔或刀具开关控制 |
| 急转角、高切向速度可能使规划超过速度和加速度限制 | PVT 急转角停速，平滑段计算受限切向速度；根据曲线速度、加速度界限延长段时间，并同步调整端点速度 | 两种规划的速度、加速度及段间位置/速度连续性检查通过 |
| 将 Spline 输入点误当成曲线必经点，会使模拟和预期不一致 | 按 SPLINE1 的等时三次 B 样条构造轨迹，包含起止附加段，并在说明中注明转角圆滑和位置松弛 | 模拟使用同一份规划模型；实际控制器的语法与时序仍待验证 |
| 仅检查输入点是否在行程内，不能排除三次曲线中间越界 | 求曲线位置极值，检查段端点及有效极值位置；同时检查当前起点和全部输入点 | 插补轨迹边界检查通过；不能代替控制器硬件限位 |
| 段时间和坐标系参数编号用错，会改变插补时间或速度单位 | 单段时间限制为不超过 4000 ms；PVT 长段拆分，Spline 超限明确报错；时间参数编号采用 5090 + 坐标系号 × 100 | 用独立常量检查 I5190、I5890、I5990、I6090、I6690，覆盖坐标系 9/10 的编号边界 |
| 旧版 PMAC 状态位定义不能直接套用到 Turbo PMAC | 核对 Turbo 手册：使能采用第一字 bit19，第二字 bit14 为保留位；电机状态按 12 位、坐标系状态按 18 位十六进制解析 | 独立状态字样例检查通过，保留位不会被误判为使能；其他控制器系列需适配 |
| 仅按计划时间结束就宣布完成，无法识别轴未到位或运行错误 | 启动前检查闭环就绪、到位和起点；运行中检查故障、限位、失能、越界及坐标系错误；完成要求轴和坐标系到位，并检查终点偏差及超时 | 模拟完成和异常状态检查通过；终点 0.05 mm 阈值是软件检查值，尚非实机验收指标 |
| HOMEZ、机械 HOME 和用户 PLC 回零含义不同，旧 Home Complete 也可能被误用 | 区分当前位置置零和机械寻零；先观察本次寻零状态变化，再判断 Home Complete、速度零和到位；加入回零超时和取消 | 重复回零、取消和超时检查通过；用户 PLC 仅提供启用/禁用接口，目标轴协议待适配 |
| 启动已排队时点击停止或关闭窗口，旧任务可能随后继续启动 | 增加启动取消标记，在准备与下载后检查；停止已拥有的路径程序时发送坐标系中止及双轴停止；主窗口等待停止回调后关闭 | 已检查关闭取消待启动任务、停止后不续跑和回零取消；通信断开时仍需控制器侧独立停机保障 |

相关实现：[TrajectoryPlanner.cs](<../Operations Control/Services/TrajectoryPlanner.cs>)、[PmacProgramWriter.cs](<../Operations Control/Services/PmacProgramWriter.cs>)、[DeviceStatus.cs](<../Operations Control/Models/DeviceStatus.cs>)、[PathView.cs](<../Operations Control/Views/PathView.cs>)。

## 4. 反馈记录、误差与时延分析

| 问题与原因 | 解决方法 | 验证结果或边界 |
| --- | --- | --- |
| 用目标点画实际轨迹会掩盖跟随误差和通信延迟 | 实际轨迹使用位置查询反馈；模拟器也按规划时间推进，并可加入滞后、停止和故障状态 | 双轴执行与反馈采样检查通过；模拟数据明确标记来源 |
| 画布历史有限，直接导出画布会丢掉早期反馈 | 运行对象独立保存采样，画布只承担显示；导出原始输入、规划段、完整反馈、误差、报告和程序 | 4101 条反馈完整导出为 4102 行 CSV，包含表头，超过画布约 4000 点的显示历史 |
| X/Y 是顺序查询，不能把两个位置当作完全同时采样 | 使用单调时钟，分别记录每轴查询中点、总查询耗时和轴间时间差；误差按每轴时间匹配参考轨迹 | 已保存和统计采样时序；查询中点是近似，尚无控制器同步锁存采集 |
| 时间误差和轮廓偏差描述不同问题，混用会误判精度 | 分别计算时间配对误差和到原始折线的轮廓距离；轮廓统计排除计划转移阶段；报告注明未完成运行 | 已知 0.2 mm 偏移检查通过；轮廓偏差不能证明时序正确或完整覆盖 |
| 空数据可能被误报为零误差，滞后估计也可能在短路径上失真 | 无采样时拒绝分析；样本和运动量足够时，在 ±1000 ms 内以 10 ms 步长拟合滞后；搜索边界结果不给出有效估计 | 已知 80 ms 滞后恢复检查通过；周期路径仍可能有歧义，结果不能替代精密时延测量 |

## 5. 主窗口整合中实际发现的问题

| 问题与原因 | 解决方法 | 验证结果 |
| --- | --- | --- |
| 独立工艺窗口让操作分散，也增加重复状态和画布 | 将路径功能改为 PathView 控件嵌入主窗口；绘图、手动控制、程序、分析、设置和日志共用一个窗口和通信会话；编辑器和日志改为嵌入显示 | 检查只有一个顶层窗口，路径、编辑器和日志均属于主窗口 |
| 整合后“手动控制”页没有出现在标签中，按钮隐藏导致定位测试失败 | 排查发现 .NET Framework 3.5 下创建句柄前插入标签页的集合状态异常；显式从旧容器移除，改用 Clear + AddRange 重建页面顺序 | 手动页恢复，定位、单步及连续点动检查通过 |
| 连接按钮和设备文字被裁切 | 排查发现 TableLayoutPanel 缺少明确行样式，父布局高 47 px，按钮却高 109 px；添加百分比行样式约束高度 | 连接和断开按钮均完整显示，控件边界检查通过 |
| 程序区右侧超出窗口，发送、下载按钮被遮挡 | 排查发现单列布局按子控件原始尺寸分配到 850 px，而可用宽度为 565 px；明确指定百分比列宽和行高，移除重复保存工具栏 | 常规及最小窗口下程序操作均可见，截图和边界检查通过 |
| 参数标签被输入框覆盖，圆弧参数在小窗口下换行后消失 | 按实际字体测量标签宽度；用小面板绑定标签和输入框；仅显示当前图形需要的字段，根据换行内容调整参数行高度 | 最小窗口下圆弧字段和鼠标跟随控件均在可见区域 |
| 路径运行期间顶部 X/Y 位置停止刷新 | 主窗口为避免重复采样暂停自身查询后，没有接收路径采样；增加 SnapshotChanged 事件，用路径反馈更新顶部读数 | 执行期间顶部位置与最新采样一致 |
| 仅禁用顶层规划参数，设置页仍能修改坐标系、滞后或变换参数 | 将高级参数、变换参数和实机确认控件纳入运行状态锁定，同时锁定竞争的手动命令、编辑和连接切换 | 运行期间相关控件禁用，规划参数不会被界面操作中途修改 |
| 长说明、重复入口和多个状态区增加阅读负担 | 保留原生按钮、分组框、字体和配色；常用操作放在顶部，详细参数放在设置页；消息集中到底部，分析页保留统计摘要 | 常规/最小窗口、程序页、分析页、设置页截图已检查 |
| 原测试依赖独立窗口和旧按钮，整合后隐藏按钮 PerformClick 不执行 | 更新测试为操作主窗体，执行按钮前选择相应页面；通过顶部停止验证跨页面中止，检查嵌入编辑器及主窗口关闭流程 | 完整界面模拟流程通过 |

- Debug、Release 编译通过，目标仍为 .NET Framework 3.5 / x86。
- 130 项基础检查和 2273 项工作流断言通过，共 2403 项。部分断言逐段检查轨迹，总数不代表功能数量。

- 工作流检查覆盖 DXF、规划边界、协议常量、误差与滞后、全量导出、主窗口执行、停止、回零取消/超时及关闭取消启动。

## 7. 尚未解决或需要实机验证的问题

| 项目 | 当前情况 | 后续处理 |
| --- | --- | --- |
| 真实设备参数和协议适配 | 控制器型号、ct/mm、方向、行程和回零参数尚未提供；现有状态及插补实现按 Turbo PMAC 编写 | 获取参数和固件版本，核对厂家通信工具、状态字及生成程序，在实机逐项验证 |
| 手动运动保护 | 路径运行已有状态和范围检查；手动点动、定位、自由命令尚未统一采用这些约束，鼠标跟随缺少轴状态互锁 | 补齐统一运动检查；确定哪些动作需要有效标定、回零状态和软件行程保护 |
| 通信断联后的停机 | 软件停止与监测均依赖通信，当前没有控制器侧看门狗或独立停机链路的实现 | 在控制器/硬件侧落实断联处理、急停和限位，并验证故障动作 |
| 程序资源和全局参数 | 路径程序会定义轴映射、清空指定程序，并设置全局 I42 及坐标系时间参数；没有自动备份、冲突检查和恢复 | 为调试预留专用坐标系/程序号；先备份和审核，后续按设备补充资源检查 |
| 用户 PLC 回零 | 当前只启用/禁用指定 PLC，没有传递所选目标轴或实现专门完成握手 | 根据现有 PLC 协议适配目标、完成、异常和取消信号；验证寻零重复性 |
| 配置保存和坐标扩展 | 标定参数未持久保存，比例只支持正值，尚无独立轴方向和工件零点偏移 | 按实机需要增加配置保存、方向及工件坐标处理 |
| 刀具或抬笔控制 | 多笔画之间有转移段，没有工具开关动作 | 实际工艺需要时再接入相应输出和互锁 |
| 真实轨迹和精度 | 当前模拟器执行数学规划，不解释任意下载脚本；上位机轮询也不属于同步采集 | 实测固件执行、停止行为和机械精度；精密验收使用控制器同步采集及量具 |

软件实现、模拟检查和实机验收分别记录，避免把“模拟运行完成”当成“设备已经验证”。
